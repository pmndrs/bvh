**[Open the examples](/examples/)** (a browser with WebGPU). Every page builds its own scene, so there is nothing to
download.

The examples live in [`examples/`](https://github.com/pmndrs/bvh/tree/main/examples): a Vite site where each page has
its source beside it and a shared overlay (which builder ran and why, build ms, SAH cost, depth, bytes, Mrays/s, a
frame-time graph). Most pages take a glTF dropped onto them.

```bash
pnpm examples:dev       # http://localhost:5310
pnpm examples:build     # examples/dist, a static site
pnpm examples:smoke     # every example in headless Chrome, each checking one thing it shows
```

## Vanilla WebGPU

Raw WebGPU and `@pmndrs/bvh` only: no three, no engine.

| Page | Shows |
| --- | --- |
| [`vanilla/hello`](https://github.com/pmndrs/bvh/tree/main/examples/vanilla/hello) | The smallest use: `createMeshLayoutBuilder` picks the builder and says why, the tree's boxes in a line pass, a picking ray, and a batch of rays whose hits are drawn straight from the GPU buffer. |
| [`vanilla/raytrace`](https://github.com/pmndrs/bvh/tree/main/examples/vanilla/raytrace) | The WGSL walk in the page's own compute kernel: one ray per pixel, shown by normal, material, instance or distance, any-hit shadows; switch tinybvh, H-PLOC and LBVH live. |
| [`vanilla/instances`](https://github.com/pmndrs/bvh/tree/main/examples/vanilla/instances) | `SceneTrees` with thousands of moving instances, runtime adds and removals, GPU first trees swapped for tinybvh's, and picking. |
| [`vanilla/builders`](https://github.com/pmndrs/bvh/tree/main/examples/vanilla/builders) | tinybvh, H-PLOC and LBVH side by side on one mesh: build ms, SAH, depth, bytes, Mrays/s on the same rays. |
| [`vanilla/fast-first`](https://github.com/pmndrs/bvh/tree/main/examples/vanilla/fast-first) | ddgi's load pattern as a recipe: `SceneTrees` places a GPU H-PLOC tree for every mesh at once, then swaps in tinybvh's from the worker pool mesh by mesh, with a timeline row per mesh while the walk traces every frame. |
| [`vanilla/workers-cpu`](https://github.com/pmndrs/bvh/tree/main/examples/vanilla/workers-cpu) | tinybvh for many meshes on the main thread, in one worker and in a pool (`createBvhWorkerPool`, no cross-origin isolation), each tree placed as it arrives while every mesh spins: time to every tree, the worst frame and long tasks of each, and a timeline row per mesh. |
| [`vanilla/workers-gpu`](https://github.com/pmndrs/bvh/tree/main/examples/vanilla/workers-gpu) | Three ways to run a GPU build on the same meshes: on the render device with no copy, on a worker's own device and transferred through the CPU, or everything in a worker with an `OffscreenCanvas`; against tinybvh's pool alone, the time to a first usable scene against the time to the best trees. |
| [`vanilla/refit`](https://github.com/pmndrs/bvh/tree/main/examples/vanilla/refit) | A deforming mesh: a compute pass poses the vertices every frame and `GpuMeshRefit` refits its tree in the scene's buffers (`meshRefitPlacement`); refit ms, SAH drift against the built tree and a fresh build, "rebuild now" and an automatic rebuild. |

### three-mesh-bvh examples, ported

Each of these is one of three-mesh-bvh's examples (MIT) running on `@pmndrs/bvh/three`, and says on the page what it demonstrates. Pages with a way to check themselves (a brute-force pass, three's own raycast) do so in the smoke run. Models are procedural unless noted: the originals download theirs.

| Page | Shows |
| --- | --- |
| [`three/clippedEdges`](https://github.com/pmndrs/bvh/tree/main/examples/three/clippedEdges) | `tree.shapecast` with a plane: a clipping plane sweeps a model, `intersectsBounds` keeps the boxes it crosses and `intersectsTriangle` turns each crossed triangle into an outline segment, capped with the stencil trick. Ported from three-mesh-bvh's `clippedEdges`. |
| [`three/collectTriangles`](https://github.com/pmndrs/bvh/tree/main/examples/three/collectTriangles) | `tree.shapecast` with a sphere as a paint brush on a mesh of hundreds of thousands of triangles; `CONTAINED` boxes hand over their triangles untested. From `collectTriangles`. |
| [`three/edgeIntersect`](https://github.com/pmndrs/bvh/tree/main/examples/three/edgeIntersect) | `tree.bvhcast` walks two trees against each other and `ExtendedTriangle.intersectsTriangle` gives the segment where every pair of triangles crosses: two spinning torus knots and the line where they meet. From `edgeIntersect`. |
| [`three/lineIntersection`](https://github.com/pmndrs/bvh/tree/main/examples/three/lineIntersection) | Raycasting a polyline of up to a million segments with a pick threshold: [`LineBVH`](/three/points-and-lines) through `computeBoundsTree({ type: LineBVH })` and `acceleratedRaycast` on the `Line`; three's `Line.raycast` is the comparison. From `lineIntersection`. |
| [`three/triangleIntersect`](https://github.com/pmndrs/bvh/tree/main/examples/three/triangleIntersect) | `ExtendedTriangle.intersectsTriangle` on its own: two triangles with draggable corners and the segment where they cross. From `triangleIntersect`. |
| [`three/voxelize`](https://github.com/pmndrs/bvh/tree/main/examples/three/voxelize) | `tree.intersectsBox(box, boxToMesh)` for the voxels on a surface and `tree.raycastFirst(ray, DoubleSide)` for the ones inside, filled a few milliseconds per frame; a dropped glTF builds its tree in `GenerateMeshBvhWorker`. From `voxelize`. |
| [`three/batchedMesh`](https://github.com/pmndrs/bvh/tree/main/examples/three/batchedMesh) | `computeBatchedBoundsTree` and `acceleratedRaycast` on a `BatchedMesh` of three geometries with hundreds of raycasters firing every frame, against three's own `BatchedMesh.raycast`. From `batchedMesh`. |
| [`three/point-cloud`](https://github.com/pmndrs/bvh/tree/main/examples/three/point-cloud) | three-mesh-bvh's `pointCloudIntersection`, ported: a [`PointsBVH`](/three/points-and-lines) over a scanned point cloud, the pointer picked through `acceleratedRaycast` with `Raycaster.params.Points.threshold`, and `BVHHelper` boxes. |
| [`three/shapecast`](https://github.com/pmndrs/bvh/tree/main/examples/three/shapecast) | A sphere, a box or another mesh moved over a spinning knot: `intersectsSphere`, `intersectsBox`, `intersectsGeometry` (tree against tree), red where they touch. |
| [`three/distancecast`](https://github.com/pmndrs/bvh/tree/main/examples/three/distancecast) | `closestPointToGeometry` joins a cylinder you move to a noise terrain; a marching-cubes volume of `closestPointToPoint` shows where either is within a distance. |
| [`three/characterMovement`](https://github.com/pmndrs/bvh/tree/main/examples/three/characterMovement) | A capsule walked through a level baked into one collider by `StaticGeometryGenerator`, pushed out of the triangles `shapecast` hands back. WASD and space; the level is three's primitives, not the original's downloaded dungeon. |
| [`three/physics`](https://github.com/pmndrs/bvh/tree/main/examples/three/physics) | Spheres thrown into a baked environment, pushed out of its triangles (`shapecast`, nearest boxes first) and off each other. |
| [`three/sculpt`](https://github.com/pmndrs/bvh/tree/main/examples/three/sculpt) | Clay, normal and flatten brushes on a welded icosphere: `shapecast` finds the vertices, the tree is refit after each stroke (whole-tree: three-mesh-bvh refits only the visited nodes). |
| [`three/selection`](https://github.com/pmndrs/bvh/tree/main/examples/three/selection) | Lasso and box selection of a 60k-triangle knot, narrowed by each tree box's screen hull, with or without the tree. |

## Comparisons with three-mesh-bvh

The [comparison](/performance/comparison) pages in `examples/compare/` (raycast, build, tree quality, queries, scene, GPU,
SDF) put the same geometry through both libraries (`compare/build` also covers the plan's async builds: worker builds and
their main-thread stalls, ours and three-mesh-bvh's); the method is on that page. Two more:

| Page | Compares |
| --- | --- |
| [`compare/skinned`](https://github.com/pmndrs/bvh/tree/main/examples/compare/skinned) | Skinned characters kept on their pose every frame: three-mesh-bvh's `SkinnedMeshBVH.refit()` on the CPU against our GPU pose pass and refit (`SceneTrees.setPose`), CPU and GPU ms per frame. What else: a plain WebGPU pass three never sees traces the refit trees. |
| [`compare/pathtracer`](https://github.com/pmndrs/bvh/tree/main/examples/compare/pathtracer) | The same small path tracer on three-mesh-bvh/webgpu's WGSL functions and on our walk (`BvhTraceNodes`): Mrays/s of the whole tracer, its closest-hit rays and its any-hit rays. What else: the scene's GPU-built trees traced by the same kernel. |

## Babylon.js

Basic: [`@pmndrs/bvh/babylon`](/engines/babylon) is "it works", not polish.

| Page | Shows |
| --- | --- |
| [`babylon/picking`](https://github.com/pmndrs/bvh/tree/main/examples/babylon/picking) | `scene.pick` over a big mesh against `BabylonBvhPicker`, picks per second for each, and the picker's `PickingInfo` under the pointer. It needs no WebGPU: it runs on Babylon's WebGL engine too (`?engine=webgl`). |
| [`babylon/gpu-trace`](https://github.com/pmndrs/bvh/tree/main/examples/babylon/gpu-trace) | Hard shadows from the WGSL walk in a Babylon `ComputeShader` on the `WebGPUEngine`'s own device (`engine._device`), bound to `SceneTrees`' buffers with no copy and blended over Babylon's render. No AO: that needs sampling, which is above the hit. |

## Node

A Node CLI plus the page that loads what it wrote. [Serialization and baking](/serialization/serialization-and-baking) has the recipe.

| Page | Shows |
| --- | --- |
| [`node/bake`](https://github.com/pmndrs/bvh/tree/main/examples/node/bake) | `pnpm examples:bake` builds a model's tree with tinybvh in Node (no GPU) and writes it with `serializeLayout`, or with `--scene` the whole scene with `serializeTraceScene`; the page checks the header with `readSerializedHeader`, loads either kind with no build at all, and its overlay says `builtBy: baked tree` or `baked scene`. An indexed tree loads next to its geometry. Traced by the WGSL walk, with the header's versions shown. `?bake=<url>` or a dropped `.bvh` loads another. |
