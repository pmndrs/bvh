`new BvhTraceNodes(renderer, source)` exposes trees to three's node system. The source is a `SceneTrees`, or any
`{ buffers: { nodes, triangles, topLevel }, version?, triangleLeaves?, positionLayout?, nodeFormat? }`.

## TSL

```text
bvh.traceClosest(origin, direction, tMin = 0, tMax = 1e30)      -> BvhTraceHit struct node
bvh.traceAny(origin, direction, tMin = 0, tMax = 1e30)          -> bool node
bvh.traceClosestMasked(origin, direction, tMin, tMax, mask)     -> BvhTraceHit
bvh.traceAnyMasked(origin, direction, tMin, tMax, mask)         -> bool
bvh.closestPoint(point, maxDistance = 1e30)                     -> BvhClosestPointHit   // with queries: true
bvh.closestPointMasked(point, maxDistance, mask)                -> BvhClosestPointHit
```

`BvhTraceHit` has `BvhHit`'s members: `t`, `instance`, `triangle`, `barycentrics`, `frontFace`, `material` and
`normal`. Read them with `hit.get('t')`. The [first build](/getting-started/first-build#threejs-on-the-gpu) has a full
example; the [path tracer example](/examples/examples) traces a bounce loop with it.

With `queries: true` the module also has the [spatial queries](/tracing/gpu-queries). `BvhClosestPointHit` has
`BvhClosestHit`'s members: `distance` (negative when nothing is nearer than `maxDistance`), `instance`, `triangle`,
`material`, `barycentrics`, `point` and `normal`, in world space. From WGSL, call `bvhClosestPoint`,
`bvhIntersectsSphere`, `bvhIntersectsBox` and `bvhIntersectsOrientedBox` by name; `shapecast: wgsl` compiles your
own shapecast hooks into the module.

## WGSL

{/* snippet: trace-nodes */}
```ts
import { wgslFn } from 'three/tsl';
import { BvhTraceNodes } from '@pmndrs/bvh/three';

    const bvh = new BvhTraceNodes(renderer, trees); // binds SceneTrees' own buffers, no copy

    // WGSL: three's wgslFn with the walk as an include, calling it by name.
    const shadow = wgslFn(
        /* wgsl */ `fn shadow(p: vec3f, l: vec3f, d: f32) -> f32 {
    return select(1.0, 0.0, bvhTraceAny(BvhRay(p, 1e-3, l, d)));
}`,
        [bvh.module],
    );
```

`bvh.module` is the walk without bindings: three binds the storage nodes. Call `bvhTraceClosest`, `bvhTraceAny` and the
masked forms by name ([Tracing in WGSL](/tracing/wgsl-walk)).

## Options

{/* snippet: trace-nodes-options */}
```ts
const bvh = new BvhTraceNodes(renderer, trees, {
    rayMasks: true, // default: traceClosestMasked and traceAnyMasked exist
    anyHitOrder: 'far', // default; 'larger' for occlusion rays from outside the model or across open space
    triangleFilter: /* wgsl */ `fn bvhTrianglePasses(candidate: BvhCandidate) -> bool { return candidate.query == BVH_QUERY_ANY; }`,
});
```

`anyHitOrder` is the any-hit walk's child order, compiled in: `'far'` (the default) is best for rays that start on
surfaces, `'larger'` for rays from outside or across open space. Answers are the same either way. On the RTX 3060
Laptop (Windows, headless Chrome 157, 2026-11-13, Sponza and Bistro interior, the median of three runs), `'larger'` was
1.11-1.48x `'far'` on instanced trees and 1.03-1.07x on merged trees with rays from the air, but 0.80-0.87x on merged
trees with rays from surfaces. The Apple M5 showed the same pattern (1.15-1.42x instanced, 0.78x merged surface rays).
Merged trees are the default, so `'far'` stays the default.

The walk is compiled for the source's formats (`triangleLeaves`, `positionLayout`, `nodeFormat`); with indexed leaves
a fourth storage node, `bvh.storage.positions`, is bound. A `SceneTrees` names them; so does an upload
(`new BvhTraceNodes(renderer, { buffers: uploadTraceScene(device, scene) })` reads them from the buffers). A source of
your own must name all three: the formats are never guessed, and a source without them is refused.

## Each frame

Call `bvh.update()` after every `SceneTrees.update` that may grow a buffer, and before three uses the nodes again. When
`SceneTrees.version` changed it swaps in an attribute bound to the new buffer, and three makes new bind groups.
Nothing recompiles.

## How it binds, and what can break

- The storage nodes are bound to `SceneTrees`' own `GPUBuffer`s, with no copy. `BvhTraceNodes` sets three's backend
  buffer for each node before three first uses it. That is three's internals, not its API; it is in one place,
  `threeInternals` in `src/three/trace-nodes.ts`.
- **Checked:** once three has used a node, `update()` checks that three still binds our buffer. A three version that
  looks buffers up differently makes `update()` throw, naming the version, rather than read a 16-byte placeholder.
- **Disposal:** `renderer.dispose()` doesn't destroy `SceneTrees`' buffers. `bvh.dispose()` releases the nodes.
- **Shader size:** the walk goes into each shader once, as plain WGSL (one loop, a 64-entry stack), and each TSL helper
  is one small function. The names are fixed, so the shader text is the same on every load.
- It needs an initialized `WebGPURenderer` on its WebGPU backend (`await renderer.init()`).
