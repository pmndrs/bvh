All figures are MiB (2^20 bytes), exact byte counts of buffers unless marked as formulas. They come from
`tools/memory-breakdown.ts` (Node, no GPU), checked against `SceneTrees.memory` on the `scene-trees-sponza` page on the
Apple M5. Your own scene: read `trees.memory` (`resident`, `transient`, `peak`).

## Against three-mesh-bvh

Two numbers per library:

- **Beyond geometry:** bytes the BVH adds to the positions and indices the app already holds. three-mesh-bvh reuses
  the positions and reorders the geometry's own index in place. Our triangle records copy the corners, so every byte
  of ours counts.
- **Total in memory:** that plus the app's geometry, counted once.

| Sponza (5.74M triangles) | Beyond geometry | Total |
| --- | ---: | ---: |
| **Ours**, default layout (nodes 185.1 + triangles 263.0 + top level) | **448.1** | **549.4** |
| Ours, indexed leaves and quantized nodes (off by default) | 225.5 | 326.8 |
| three-mesh-bvh 0.9.18, defaults (CENTER, leaf 10) | 51.2 | 152.6 |
| three-mesh-bvh, SAH, leaf 4 | 109.3 | 210.7 |

| Bistro exterior (2.83M triangles) | Beyond geometry | Total |
| --- | ---: | ---: |
| **Ours**, default layout | **210.1** | **275.9** |
| Ours, indexed and quantized | 115.3 | 181.1 |
| three-mesh-bvh, defaults | 26.3 | 92.1 |
| three-mesh-bvh, SAH, leaf 4 | 53.4 | 119.2 |

- Per triangle, we add 81.8 bytes (33.8 of nodes, 48 of record); three-mesh-bvh adds 9.3 (CENTER) to 20.0 (SAH leaf 4).
- Our nodes are 64 bytes with two child boxes and leaves of about 1.9 triangles (tinybvh's SAH); three-mesh-bvh's are
  32 bytes with one box and leaves of about 7. Small leaves are part of why the walk is fast.
- The comparison counts what each library adds. An app that also keeps the geometry on the GPU for rendering holds it
  either way.

## The load's peak

The GPU build is the biggest number. One H-PLOC batch of all of Sponza holds 1,482.4 MiB (inputs 101.3, scratch 745.6,
outputs 635.5), and `SceneTrees.memory.peak` measured 1,482.7. The default [build-peak cap](/builders/fallbacks-and-limits#the-build-peak-cap)
(256 MiB batches, one after another) takes the peak to 711.0 MiB, with the first trees no later (Apple M5, indicative).

## Other memory

- **Workers:** each tinybvh worker keeps a 64 MiB WebAssembly heap; the default pool of up to 4 holds 256 MiB of CPU
  memory while it lives. Inputs are copied in (one mesh per worker at a time), results transferred out.
- **Deforming meshes:** the GPU refit's buffers (32 bytes of box per triangle, plus topology and scratch) and, with
  quantized nodes, a 64-byte `f32` copy of the nodes. Static scenes pay none of it.
- **Merged static instances:** the same resident bytes as instanced, plus a CPU plan of 161.6 MiB on Sponza while the
  merged mesh builds.
- **`gpuTreeOutputs: 'adopt'`:** no copy at load, but the node buffer keeps one node per triangle: 613.6 MiB settled on
  Sponza against 470.0.

## Levers

| Lever | Default | Saves on Sponza | Cost (Apple M5, indicative) |
| --- | --- | --- | --- |
| Build-peak cap (`gpuMaxBatchBytes`) | **on**, 256 MiB | 771 MiB of peak | none measured on first trees |
| Indexed leaves (`triangleLeaves: 'indexed'`) | off | 130.1 MiB resident (141.4 with packed positions) | trace 0.83-0.99x (`vec4`), 0.75-0.92x (packed) |
| Quantized nodes (`nodeFormat: 'quantized'`) | off | 92.6 MiB resident | trace 0.93-0.97x; SAH +0.01-0.66% |
| Both | off | 222.6 MiB resident | |
| Compact hit records (`hitNormal: false`) | off | 16 bytes per ray in a batch | none: the 40-byte record measured as fast |
| Smaller leaves (`maxLeafPrimitives`) | 8 | nothing: tinybvh picks about 1.9 per leaf anyway (8 against 4 saved 0.5 MiB) | |

The two layout variants stay off until the RTX 3060 is measured. Design notes and every table behind this page:
[`docs/internals/design/memory.md`](https://github.com/pmndrs/bvh/blob/main/docs/internals/design/memory.md).
