# Examples

A Vite multi-page site (BX.5, BX.6, BX.9 in docs/internals/design/bvh-package-split.md). Each example is one page with its source beside it and the shared overlay.

```
pnpm examples:dev                       # http://localhost:5310
pnpm examples:build                     # examples/dist (static)
pnpm examples:smoke                     # every example, headless Chrome, through the GPU runner
pnpm examples:smoke --filter three-raycast
```

The library is read from source through its public names only: `@pmndrs/bvh`, `@pmndrs/bvh/three` and `@pmndrs/bvh/worker` are aliased to `src/index.ts`, `src/three/index.ts` and `src/worker/index.ts` (`vite.config.ts`, `tsconfig.examples.json`). ESLint refuses a path into `src/` here. `examples/` is outside the library build (`tsconfig.build.json` only reads `src/`) and is type-checked by `pnpm typecheck`.

## The shell

- `index.html` lists every example from `shared/examples.ts` (also the build inputs and the smoke list).
- `shared/overlay.ts` is the overlay every page shows: `builtBy` and `fallbackReason`, build ms (CPU wall time; GPU timestamps where the device has `timestamp-query`, else what was measured, said so), SAH cost, depth, nodes, triangles and bytes, Mrays/s where rays are traced, a main-thread frame-time graph, a back link and "Source ↗".
- `shared/app.ts`: `WebGPURenderer` (three requests every adapter feature, `subgroups` and `timestamp-query` included), `deviceFromRendererAsync`, camera, orbit controls, the frame loop.
- `shared/loader.ts`: defaults from three's built-in geometries; `?model=<path>` loads a glTF from the assets base; drag and drop of a `.glb` (or a `.gltf` dropped together with its `.bin` and textures).
- Picking and batch rays are the library's `GpuRays` (over a `SceneTrees` or an uploaded scene, both a `TraceSource`); `shared/gpu-timer.ts`: timestamp queries for the pages' own passes (and the `timestampWrites` of `SceneTrees.update`); `shared/stats.ts`: overlay numbers from a layout (`treeSahCost`) or a `SceneTrees` (`onTree` events, `counts`, `meshStatus`, `memory`).
- `shared/smoke.ts`: smoke mode (below).
- `shared/builders.ts`: one mesh's tree from a chosen builder, timed (CPU wall time, GPU timestamps), with the chooser's fallback; the inspector and the vanilla pages share it.
- `shared/vanilla/`: the three-free shell of the vanilla pages (below). `overlay.ts`, `smoke.ts`, `stats.ts`, `gpu-timer.ts`, `builders.ts` (also `assembleLayouts`) and `assets.ts` are three-free too; `app.ts`, `loader.ts` and `compare.ts` are the three shell. ESLint refuses three, `@pmndrs/bvh/three` and the three shell in `vanilla/` and `shared/vanilla/`.

### Assets

Nothing large is committed. The dev server serves `BVH_ASSETS_DIR` (default `../webgpu-ddgi/assets`, the GPU runner's variable) at `/assets/`, so:

```
BVH_ASSETS_DIR=../webgpu-ddgi/assets pnpm examples:dev
# http://localhost:5310/three/load-gltf/?model=downloads/sponza-intel/main_sponza/NewSponza_Main_glTF_003.gltf
```

`?assets=<url>` points the loader at another base (a built site has no `/assets/`).

### Smoke runs

`pnpm examples:smoke` is `node tests/gpu/run.ts --examples`: the runner serves this site with its own Vite config (plus the runner's preflight page), opens each example with `?token=`, and judges it like a test page. An example in smoke mode runs as it would for a person and, once it has shown what it is about, calls `ready()` (`shared/smoke.ts`), which leaves the report on `window.__gpuTestReport` with the overlay's numbers as `data`. Uncaught errors, unhandled rejections, WebGPU `uncapturederror`s, console errors and timeouts fail it. Each example also checks one thing it shows (for example, `acceleratedRaycast` agreeing with three's raycast, the GPU batch hitting).

## Vanilla WebGPU examples (P4 item 1)

Raw WebGPU and `@pmndrs/bvh` only: no three, no engine. They prove the "not a three library" claim.

- `shared/vanilla/app.ts`: a `GPUDevice` asked for `subgroups` and `timestamp-query` when the adapter has them, plus the adapter's storage limits; a WebGPU canvas; an orbit camera (`camera.ts`: a view-projection matrix for raster passes, the ray basis for compute passes, packed camera rays); the shared overlay; a frame loop of `update` (may await a readback) then `render` (records into the frame's encoder; the loop submits).
- `shared/vanilla/geometry.ts`: procedural meshes (torus knot, sphere, box, torus, ground) as plain `positions` and `indices`, scenes of meshes and column-major instances with a material number, `mergeToWorld`. `gltf.ts`: a minimal glTF reader (positions, indices, node transforms; `.glb` or `.gltf` with its `.bin`; no Draco, meshopt or quantized positions) for `?model=` and drag and drop.
- `shared/vanilla/raycast-view.ts`: the ray-cast kernel the pages share: `traceModuleWgsl` in the page's own compute shader, one closest-hit ray per pixel, a colour from the hit alone (normal, material, instance, triangle, distance), optional any-hit hard shadows, each pixel's hit record kept for picking, and a blit pass. A demo of the walk, not a renderer: no sampling, BSDFs or accumulation (the scope rule in HANDOFF.md).

## Node bake (BX.11)

A Node CLI and the page that loads its file with no build at all. The CLI is `pnpm examples:bake [model.glb|.gltf] [--out file.bvh] [--leaf n] [--indexed] [--quantized]`: tinybvh's WebAssembly builds the tree (no GPU), `serializeLayout` writes it. With no model it bakes the default torus knot (6,400 triangles) to `node/bake/fixtures/torus-knot.bvh`, the 0.5 MB fixture the page loads (and the smoke run needs). A glTF's meshes are merged into one world-space mesh, because a bake is one mesh's tree; there is no scene-level file. `bake.ts` (the CLI's functions, also used by the unit test, `docs/snippets/node-bake.test.ts`), `model.ts` (the default mesh, browser-safe), `cli.ts`, and the page (`index.html`, `main.ts`). The script runs the TypeScript with `--experimental-transform-types` and the compare runner's resolve hook (`compare/node/register.mjs`), so it needs no `pnpm build`.

| Page | Shows | Smoke check |
| --- | --- | --- |
| `node/bake` | The baked file read with `deserializeLayout` (fetch and deserialize ms, no build), uploaded and traced by the shared ray-cast view; the overlay's `builtBy` is `baked file: <name>`, with the file's header versions beside this package's. `?bake=<url>`, or a dropped `.bvh` (an `indexed` bake is refused: the page has no geometry to load it next to) | the view's 1,024 pixels agree with the CPU walk over the loaded tree (at least 50 hits); then the default model is built fresh with tinybvh in the page and its nodes, triangles and parents are byte-identical to the baked file's |

Documented in `docs/serialization/serialization-and-baking.mdx`: the bake-at-build-time recipe (a script, a Vite plugin sketch), the version check and what invalidates a bake. The smoke run's screenshot under SwiftShader showed only the overlay (the canvas came out blank); the report has the numbers.

## Comparison pages (`compare/`, BX.10)

Each runs the suites of `compare/core/` (the same as `pnpm compare:node`) on the page's mesh (`?scene=furnished-room`, `?scene=sponza`, `?model=`, a torus knot by default; meshes merged into one world-space mesh), shows a table with every answer's agreement with ours, works live with the library chosen in the overlay, and has a "what else you can do" box. Smoke runs use a 20k-triangle knot and short timings; `BVH_PAGE_QUERY='scene=sponza&full'` gives the runner a full run, whose CSV rows come back in the report (`data.csv`). Results and method: `compare/RESULTS.md`.

| `compare/gpu` | GPU closest and any hit against three-mesh-bvh/webgpu, paired rounds | a GPU-built tree traced by the same kernel | every ray agrees |
| `compare/sdf` | SDF build time on the GPU against three-mesh-bvh's `webgpu_sdfGeneration` kernel (its v0.9.18 example's WGSL as published, SAH tree), 32³/64³/128³, paired rounds; ours signed (three all-hit rays, parity vote) and unsigned (closest point alone, the floor of either); the same welded geometry, centred on the origin because their kernel's `vec4f(p, 1) * matrix` is right only for a centred box | SceneTrees' GPU-built tree straight into a three texture (`generateSdfTexture`), shown as a slice | every voxel's distance agrees with ours (theirs and our unsigned field); signs are compared and reported, not gated (one +Z ray against a vote of three) |

## Public-API gaps the examples ran into

- Open: `SceneTrees` keeps no CPU copy of its trees, so there is no SAH cost per tree for the overlay.
- Done: `SceneTrees.update(encoder, { timestampWrites })` brackets everything the update records (`vanilla/instances` shows it; `GpuBracket` is gone), and `timestamps: true` times the GPU build batches (`counts.gpuBuildTimestampMs`; `counts.gpuBuildMs` stays submit-to-stats wall time).
- Done: `SceneTreesObject3DSync.meshHandles` lists its mesh handles; the three pages pass it to `SceneTreesLog.tree` instead of collecting handles from `onTree` events.
- Done: the GPU walk's step counters are public as an opt-in compile option (`traceModuleWgsl({ counters: true })`: `bvhTraceClosestCounted`/`bvhTraceAnyCounted` returning `BvhWalkCounts`; `TraceBatchKernel` `counters: true`; `GpuRays.countWalk`), cut from the walk's own text as the benches' copy is; the inspector's heat map runs on the GPU.
- Done: `GpuRays` (picking and batches: buffers, dispatch, readback, hit decoding) is in the package now; the pages use it.
- Done: `createMeshLayoutBuilder` has `prepare: false` with `builder.prepare()` (setup apart from the build) and `onGpuBatch` (each GPU batch's pass from timestamps, and its wall time); the GPU builders' `buildMany` takes `timestampWrites`. `vanilla/hello` shows the build's GPU time, and `shared/builders.ts` (`vanilla/builders`, the inspector) builds through the chooser instead of driving batches itself.
- Done: `createMeshLayoutBuilder({ prefer: 'tinybvh' })` still reports `fallbackReason: 'the CPU builder was asked for'` (its meaning is unchanged and documented), and `builder.fallback` is true only for a real fallback; `vanilla/raytrace` and `vanilla/hello` show `fallback ? fallbackReason : null`.
- Done: an uploaded scene (`uploadTraceScene`) and a `SceneTrees` are one type, `TraceSource` (`traceBuffersOf` reads either's buffers); `traceSourceOf` is gone.
- Won't (scope rule): the plan's `vanilla/raytrace` had ambient occlusion; it would need random directions (sampling), which the scope rule leaves to renderers above the package, so the page has hard any-hit shadows only.
- Done: `SceneTrees` has `onBuild` (each mesh's build requested, started and finished, per builder, with the outcome and, with `timestamps`, the GPU batch's time) beside `onTree`, and `BvhWorkerPool` has `onBuild` (queued, started, finished per build) and a per-build `onStart`. `fast-first` and `workers-cpu` draw their timelines from `SceneTrees`' events; `shared/vanilla/watched-pool.ts` is gone.
- Done: `SceneTrees.rebuild(mesh)` rebuilds a deforming mesh now from its GPU pose (`three/skinned` has a button; `meshStatus(mesh).deforming` says which meshes deform), and `SceneTrees.placeTree(mesh, layout)` places a tree the app built (`vanilla/workers-gpu`'s worker-device way uses it instead of assembling and uploading a scene of its own). `vanilla/refit` keeps driving `GpuMeshRefit` on an uploaded scene on purpose: it is the page for that lower-level API (a refit in the app's own buffers at `meshRefitPlacement`'s offsets).
- Done: `SceneTrees` has a GPU-only mode, `refine: false` (tinybvh builds only what the GPU refuses); `vanilla/workers-gpu` has a "render device, GPU only" row.

## Library issues the examples ran into

- **Pose-pass compile race (fixed):** the sync started each pose variant's `compileComputeAsync` without waiting for it, and an `update()` before three's async pipeline existed dispatched `setPipeline(undefined)` (a TypeError, seen on the M5 with nine skinned meshes on one geometry). `update()` now skips posing an object while its variant compiles (`poseCounts.waiting`; its tree keeps its last pose), and `await sync.ready` has every object posed from the first update. `three/skinned` doesn't wait.
- **three's `SkinnedMesh` raycast culls with a stale sphere:** `SkinnedMesh.raycast` tests `mesh.boundingSphere`, which three computes once (the renderer's frustum culling does, at the first frame) and never again. Rays that hit the current pose outside that sphere miss in three's raycast. The `three/skinned` check calls `computeBoundingSphere()` for the frozen pose before comparing.
- **Limits:** a scene past 128 MiB of triangles needs `requiredLimits` on the `WebGPURenderer` (three asks for WebGPU's defaults). `shared/app.ts` asks for the adapter's `maxStorageBufferBindingSize` and `maxBufferSize`; without it, a 1.8 M-triangle scene fails with a clear `RangeError` naming the limit.
